Comparaison de couverture Karate

Comparaison entre Claude Opus 4.5 v0 et Claude Opus 4.5 (new prompt) pour les tests Petstore.
Total scénarios : v0 ≈ 220  •  v1 ≈ 68
v0 : petstore-karate-project v1 : karate-petstore-tests Couverture fonctionnelle Cas négatifs & bornes Tests transverses

Synthèse globale

v0 est un framework de tests Petstore très complet et structuré (16 features), avec des helpers réutilisables, de nombreux profils Maven (par risque, type de test, domaine et environnement) et une forte couverture des dimensions fonctionnelles et non fonctionnelles (contrat, contenu, sécurité, performance, intégration, gestion d’erreurs), ainsi que des rapports et métriques détaillés.

v1 est un projet plus léger et focalisé (3 grandes features Pet/Store/User + 4 classes Java), en français, avec un POM simplifié et des scénarios centrés sur les principaux flux métier (CRUD + E2E par domaine) et quelques cas négatifs/bornes, davantage adapté à un contexte pédagogique ou de démonstration.

Globalement, les cas métiers critiques existent dans les deux projets, mais v0 offre plus de variantes, de cas limites et de validations de structure, tandis que v1 privilégie la lisibilité et la simplicité plutôt que l’exhaustivité et la configurabilité.

Tests transverses

Contrat, contenu, sécurité, performance, intégration…
Type de test v0 v1 Commentaire
Contenu / négociation de contenu Oui content-negotiation.feature Partiel v0 a un module dédié (JSON vs XML, headers); v1 ne gère que quelques headers au fil des scénarios.
Contrat / schéma de réponse Oui schema-validation.feature + schémas dans karate-config.js Partiel v0 se rapproche d’une vraie validation de contrat; v1 utilise surtout des match locaux.
Performance Oui performance-tests.feature N/A Tests de temps de réponse et d’objectifs de performance uniquement présents dans v0.
Sécurité Oui security-tests.feature Partiel v0 isole les cas d’auth, d’absence de clé, etc.; v1 ne traite pas la sécurité comme un sujet séparé.
Gestion d’erreur / robustesse Oui error-handling.feature + nombreux cas négatifs Partiel v0 a une vraie stratégie d’« error guessing »; v1 garde les principaux cas négatifs seulement.
Intégration multi-domaines Oui integration-tests.feature N/A v0 a des E2E reliant User + Pet + Store; v1 ne fait des E2E qu’à l’intérieur d’un domaine.

Cas de tests non communs

Présents uniquement dans v0 ou uniquement dans v1

Uniquement dans v0 (v1 = N/A)

  • Features dédiées : content-negotiation.feature, schema-validation.feature, performance-tests.feature, security-tests.feature, integration-tests.feature, error-handling.feature.
  • Scénarios Pet : caractères spéciaux poussés, très longues chaînes, tableaux multiples avec tailles exactes, content-type XML, tests explicites sans api_key.
  • Scénarios Store : cohérence fine de l’inventaire avant/après, quantités extrêmes, application stricte des règles d’ID de la doc.
  • Scénarios User : variantes multiples de userStatus, bulk create avancé avec vérification et nettoyage, tests de headers (ex. Set-Cookie) et identifiants spéciaux.
  • Utilitaires : features common-utils.feature, pet-helpers.feature, store-helpers.feature, user-helpers.feature + POM riche en profils (critical, performance, security, integration, etc.).

Uniquement dans v1 (v0 = N/A)

  • Organisation très pédagogique : un fichier unique par domaine (features/pet/pet.feature, features/store/store.feature, features/user/user.feature) avec descriptions en français.
  • POM allégé adapté à un contexte de TP / démo : profils principaux smoke, regression, pet, store, user, sans complexité supplémentaire.
